# SUPER DASH

A browser rhythm platformer. You hold one button, the music sets the pace, and
every jump lands on the beat. It has eight game modes, practice mode with
checkpoints, a full level editor and eight original levels with an original
soundtrack.

Everything in the game is made in code: the art is drawn with canvas and
Pixi, the music is composed and synthesized by an in-house synth, and every
level and name is original. No external assets are loaded apart from two
Google Fonts.

## Controls

| Action | Keys |
| --- | --- |
| Jump / fly / flip (hold to keep going) | Space, Up, W, left click, tap anywhere |
| Pause | Esc, P, or the pause button |
| Restart | R |
| Practice: place / remove checkpoint | Z / X, or the on-screen buttons |
| Level select | Left / Right, swipe, click a card; Enter to play |

## Running it

Requires Node 22+.

```sh
npm ci
npm run dev        # dev server at http://localhost:5173
npm run build      # typecheck + production build into dist/
npm run preview    # serve dist/ at http://localhost:4173
npm test           # Vitest: physics, modes, triggers, levels, replays, perf
npm run e2e        # build, then the Playwright suite (Chromium)
npm run levels     # regenerate the 8 shipped levels and their replays
```

Useful URL parameters (handy for testing and sharing):

| Parameter | Effect |
| --- | --- |
| `?level=<id>` | Start a level directly, e.g. `?level=neon-footsteps` or `?level=test-ship` |
| `?level=<id>&replay` | Watch the level's stored winning replay |
| `?level=<id>&practice` | Start in practice mode |
| `?editor` (`&level=<id>`) | Open the editor (optionally on a level) |
| `?stress=24000` | Generate and auto-play a dense performance test level |
| `?gallery` | Show every generated texture and icon |

## How it works

- **Simulation** (`src/core/sim`): a deterministic 240 Hz fixed-step sim,
  decoupled from rendering and interpolated for any refresh rate. All tunables
  live in `src/core/physics.ts` (1 block = 30 units). The sim is plain data, so
  checkpoints are full-state copies and replays reproduce exactly.
- **Music sync** (`src/game/clock.ts`): while music plays, level time follows
  the audio clock. If they drift apart by more than one 60 Hz frame the clock
  snaps back; smaller differences are slewed out.
- **Input**: `keydown` and `pointerdown` events are timestamped and applied on
  the sim tick they belong to, not on the next frame.
- **Rendering** (`src/render`): PixiJS v8 with WebGL (canvas fallback). Object
  art is pre-drawn into texture atlases at load, the level is split into
  4-block chunks, and only visible chunks get sprites (pooled).
- **Audio** (`src/core/audio`): songs are written as code in `songs.ts` and
  rendered by the synth in a Web Worker the first time they are needed.
- **Levels** (`src/levels`): compact JSON. The shipped levels are generated by
  a music-driven composer in `scripts/` that places inputs on the song's beat
  grid, builds the level around the real sim trajectory, and stores the
  verified winning replay in each level file. `tests/levels.test.ts` replays
  every level and fails if any can't be beaten.
- **Persistence**: settings, icons, progress and saved levels go in
  `localStorage` (every access wrapped in try/catch); imported songs go in
  IndexedDB.

To rename the game, change `GAME_TITLE` in `src/config.ts`. Design decisions
and the milestone log are in [PLAN.md](PLAN.md).

## Level format

```jsonc
{
  "v": 1,
  "meta": {
    "name": "My Level", "author": "me", "difficulty": "normal",
    "song": "neon-footsteps", "offset": 0, "bpm": 128,
    "mode": "cube", "speed": 1, "length": 300,
    "colors": { "bg": "#2b2fd6", "g": "#1a1c8f", "line": "#c8f0ff", "1": "#5cc8ff" }
  },
  // [type id, x, y, extras?]: centers in blocks; extras such as rotation (r),
  // flip (fx/fy), color channel (c), groups (g) and trigger settings
  "objects": [[1, 10.5, 0.5], [20, 14.5, 0.5], [101, 20, 5, { "t": 1, "dy": 2, "d": 0.5 }]]
}
```

The editor exports and imports this format, and the in-game "Create" page can
import a `.json` file directly.

## Performance

`npm test` includes a 24,457-object stress level: it compiles in about 50 ms
and simulates about 860x faster than real time. In the browser
(`?stress=24000`), per-frame update work averages about 0.3 ms, and the
main thread is over 95% idle in a CPU profile. Textures and shaders are
warmed up behind the start screen, so a level's first frame doesn't hitch.

## Deploying to Vercel

The repo deploys as a static site. `vercel.json` sets the build command
(`npm run build`), the output directory (`dist`), a fallback that sends every
route to `index.html`, and long-lived immutable cache headers for the hashed
files in `/assets`.

To make every push to `main` deploy automatically:

1. Sign in at [vercel.com](https://vercel.com) and choose **Add New... →
   Project**.
2. Under **Import Git Repository**, pick this GitHub repository (grant the
   Vercel GitHub app access to it if it isn't listed).
3. Leave the settings as detected (framework **Vite**; build, output and
   install commands come from `vercel.json`) and click **Deploy**.
4. That's it: from now on each push to `main` triggers a production
   deployment, and pushes to other branches get preview URLs.

From a terminal, `npx vercel --prod` deploys the current checkout as well.
