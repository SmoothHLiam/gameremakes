# SUPER DASH — Plan

A browser rhythm platformer: one button, a world that scrolls to the beat, and
physics tuned to feel tight and fair. Everything (art, music, levels, names) is
original and generated in code.

## Name

The working title requested was "GEOMETRY DASH". That is the trademarked name of
an existing commercial game, and the asset rule for this project says no names
from existing games, so the game ships as **SUPER DASH** (the requested
fallback). The title lives in one constant, `GAME_TITLE` in `src/config.ts`.

## Architecture

```
src/
  config.ts            game title + build-level config constants
  core/                pure TypeScript, no DOM. Runs in browser, worker and Node.
    physics.ts         EVERY tunable physics number (speeds, gravity, jumps, hitboxes…)
    dmath.ts           deterministic math (polynomial sin/cos, easing) for sim use
    objects.ts         object registry: id → kind, size, hitbox, palette category
    level.ts           level JSON types, parse/validate/serialize (compact format)
    sim/
      world.ts         compiled level: typed arrays, spatial chunks, trigger list
      state.ts         SimState (plain data, cheap to clone → checkpoints)
      player.ts        per-mode movement rules
      collide.ts       AABB / slope / circle tests
      triggers.ts      trigger runtime (move/alpha/color/rotate/pulse/toggle/shake)
      sim.ts           Simulation: fixed 240 Hz step, input timeline, events
      replay.ts        replay format + headless runner
    audio/
      synth.ts         pure-JS offline synthesizer (oscillators, filters, drums, fx)
      song.ts          song description DSL + renderer
      songs/*.ts       the original soundtrack (8 level songs, menu loop, practice loop)
  app/                 browser glue: audio engine, input, storage, settings
  render/              PixiJS v8 renderer, generated textures, particles, camera
  game/                GameSession: sim + audio clock + renderer + HUD
  ui/                  DOM menus over the canvas (splash, main, level select, …)
  editor/              in-game level editor
  levels/              shipped level JSON (generated by scripts/build-levels.ts)
scripts/
  build-levels.ts      runs level builders, verifies replays, writes JSON
  levels/*.ts          level builder scripts (one per shipped level)
tests/                 Vitest unit tests (physics targets, determinism, replays)
e2e/                   Playwright smoke test
```

### Simulation

- Fixed timestep, **240 Hz**. `Simulation.step()` advances exactly one tick.
  Rendering interpolates between the previous and current tick's render state.
- **Deterministic**: the sim only uses `+ - * /` and `Math.sqrt` / `Math.floor`
  style exact ops (IEEE-754 guarantees identical results everywhere). Anything
  that needs trig (rotate triggers, dash-orb angles) uses polynomial
  implementations in `dmath.ts`. Visual-only values (ship tilt, particles)
  may use `Math.sin` etc. because they never feed back into the sim.
- Input is a timeline of `(tick, down|up)` edges. Live play timestamps DOM
  events (`event.timeStamp`) and maps them to the tick they belong to. A replay
  is the same list, so replays and tests share the exact code path.
- World units: 1 block = 30 units, y up, ground surface at y = 0.

### Clock and audio sync

- While music plays, level time comes from the audio clock:
  `levelTime = (audibleContextTime − songStartContextTime) + startLevelTime`,
  where audibleContextTime uses `getOutputTimestamp()` so what you see matches
  what you hear (output latency compensated).
- Each frame the sim clock is compared with the audio clock. Small differences
  are slewed out gently; if they disagree by more than one display frame
  (1/60 s) the sim clock snaps to the audio clock (sim catches up by running
  extra ticks, or holds if it is ahead — the sim never rewinds).
- Songs are rendered to AudioBuffers by a pure-JS synth in a Web Worker before
  a level starts (no hitches during play). Seeking = `source.start(when, offset)`.

### Spatial chunking

Level objects are bucketed into 4-block-wide columns. Collision touches only the
chunks overlapping the player; rendering only builds sprites for chunks in view
(sprites come from pools, so nothing is allocated mid-run). Objects in groups
targeted by move/rotate triggers are inserted into every chunk their motion
envelope can reach, so lookups stay correct while they move.

### Rendering

- PixiJS v8, WebGL preferred. Pixi is asked for `webgl`; if no WebGL context
  can be created we fall back to Pixi's WebGPU, and if neither exists a
  plain message explains it (the menus still work).
- All textures are drawn with Canvas2D at load time and packed into one atlas,
  so the world draws in a handful of batches. Textures are white/grey so color
  channels apply via tint.
- Glow: glow-enabled objects and the player get an extra sprite in a glow layer
  that has a `BlurFilter` + additive blending.
- 16:9 letterboxed canvas; DOM UI is laid out at 1280×720 and scaled to match.

## Physics (targets, all in `src/core/physics.ts`)

| quantity | value |
| --- | --- |
| speeds (blocks/s) | 8.4, 10.4, 13.0, 15.6, 19.2 |
| cube jump velocity | 600 u/s |
| cube gravity | 2790 u/s² |
| cube peak | ≈ 2.15 blocks |
| cube airtime | ≈ 0.43 s → ≈ 4.5 blocks at normal speed (clears a 3-block spike row) |
| cube terminal velocity | 810 u/s |
| mini scale | 0.6 (hitbox), jump velocity × 0.8 |

Mode summary:

- **Cube**: jumps while held and grounded (auto-jumps on landing). Rotates
  90° per full jump (spec), snaps to nearest 90° on landing. No ceiling: hitting
  the underside of a block kills (inner hitbox), like walls.
- **Ship**: hold = thrust, release = fall, capped vertical speed; tilt follows velocity.
- **Ball**: fresh press while grounded flips gravity (with a small push). Rolling spin.
- **UFO**: every fresh press sets an upward hop velocity, mid-air included.
- **Wave**: vy = ±vx (45°), mini = ±2·vx (63°). No acceleration. Slides on surfaces.
- **Robot**: press when grounded starts a jump; holding keeps a constant
  boost velocity up to a max boost time.
- **Spider**: fresh press while grounded teleports to the opposite surface and flips gravity.
- **Swing**: fresh press flips gravity at any time; gravity pulls toward the
  current surface; capped speed.

Hitboxes:

- Outer (solid) box = player size. Used to land on blocks and to touch hazards,
  orbs, pads, portals and coins.
- Inner box = 40% of the outer box. If it overlaps any solid, the player dies.
  This is what makes side hits deadly while landing on top is safe.
- Landing snap: when the outer box overlaps a solid while moving toward it
  and the penetration is ≤ 9 units (scaled for mini), the player snaps onto the
  surface. Ceilings resolve the same way only for modes that have them.
- Spike hitbox is a small box (0.2 × 0.4 blocks) in the spike's core; saws use
  a circle at 65% of the visual radius.

## Decisions on ambiguous points

- **Name**: SUPER DASH (see above).
- **"Resync if they disagree by more than one frame"**: one display frame at
  60 Hz (16.7 ms). Audio clocks tick in 3–20 ms chunks, so a one-*sim*-frame
  (4 ms) threshold would snap constantly; within the threshold we slew.
- **Shallow slopes**: the spec says 22.5°. A 22.5° slope never lines up with the
  block grid, which makes building and fair timing worse, so shallow slopes are
  2:1 (26.6°), the grid-aligned slope closest to 22.5°. Steep slopes are 45°.
- **Cube spin**: exactly 90° per full jump as specified (constant in physics.ts).
- **Press buffer**: 2 sim ticks (8.3 ms) for orbs, and also for ball/spider
  surface presses, so a press just before landing isn't eaten.
- **Orb vs ground jump**: an orb takes priority over a ground jump on the same press.
- **Dual**: second player spawns mirrored inside the play area with opposite
  gravity. Dual always uses a bounded play area (the dual portal defines it if
  the current mode is unbounded). Mode / size / speed / mirror / dual portals
  apply to both players when either passes; gravity portals, orbs and pads are
  per player.
- **Rotate triggers on solids**: visuals rotate freely; collision boxes orbit
  the rotation center but stay axis-aligned (their own rotation snaps to 90°).
  Hazards' hitboxes rotate fully.
- **Toggle trigger**: hidden groups also lose collision. Alpha only affects visuals.
- **Custom songs** imported in the editor are stored in IndexedDB (localStorage
  is too small for audio); level JSON itself stays in localStorage.
- **Auto checkpoints** (practice) are taken every 2 s but only committed if the
  player survives the next 0.5 s, so they don't land in unavoidable deaths.
- **Shipped levels** are produced by builder scripts that place obstacles
  around an intended input timeline, then verified in the real sim; the
  verified timeline is stored as the level's winning replay.
